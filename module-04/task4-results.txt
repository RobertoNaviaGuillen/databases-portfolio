## 1. A view exposes a safe subset for report readers
$ sqlite3 module-04/edge.db DROP VIEW IF EXISTS machine_health; CREATE VIEW machine_health AS
  SELECT s.machine_id, s.metric, MAX(r.value) AS peak, COUNT(*) AS n
  FROM sensor s JOIN reading r USING(sensor_id) GROUP BY s.machine_id, s.metric;
(exit code 0)

$ sqlite3 -header -column module-04/edge.db SELECT * FROM machine_health;
machine_id  metric   peak    n
----------  -------  -----  ---
cnc-01      temp_c    60.0  502
cnc-01      vib_rms  1.899  501
(exit code 0)

## 2. Read-only at the file level
$ chmod 444 module-04/edge.db
(exit code 0)

$ ls -l module-04/edge.db
-r--r--r-- 1 Flaku 197609 102400 Nov 11 20:29 module-04/edge.db
(exit code 0)

On Windows, Git Bash's chmod 444 sets the read-only file attribute (R):
$ cmd //c attrib module-04\edge.db
A    R               C:\Users\Flaku\OneDrive\Documentos\HSBI UNIVERSIDAD\tercer semestre\Databases\databases-portfolio\module-04\edge.db
(exit code 0)

$ sqlite3 module-04/edge.db SELECT COUNT(*) FROM reading;
1003
(exit code 0)

$ sqlite3 module-04/edge.db DELETE FROM reading;
Error in 2nd command line argument: attempt to write a readonly database
(exit code 1)

## 3. Read-only at the connection level (file writable again)
$ chmod 644 module-04/edge.db
(exit code 0)

$ sqlite3 file:module-04/edge.db?mode=ro SELECT COUNT(*) FROM reading;
1003
(exit code 0)

$ sqlite3 file:module-04/edge.db?mode=ro DELETE FROM reading;
Error in 2nd command line argument: attempt to write a readonly database
(exit code 1)

The same with PRAGMA query_only on a normal connection:
$ sqlite3 module-04/edge.db PRAGMA query_only = ON; DELETE FROM reading;
Error in 2nd command line argument: attempt to write a readonly database
(exit code 1)

## 4. Check: nothing was deleted
$ sqlite3 module-04/edge.db SELECT COUNT(*) FROM reading;
1003
(exit code 0)
